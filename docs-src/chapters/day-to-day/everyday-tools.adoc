[#everyday-tools]
== Everyday Tools

=== Your shell

Bash, on purpose. It's what every tutorial already assumes. A few things are added on top:

* *Syntax highlighting and autosuggestions* as you type. Press kbd:[→] or kbd:[End] to accept a
  suggestion.
* *Fuzzy history and file search*: kbd:[Ctrl+R] searches history, kbd:[Ctrl+T] finds a file,
  kbd:[Alt+C] finds and jumps into a directory.
* *Smarter `cd`*: `z <part of a path>` jumps there by frecency.
* *Modern replacements*, all optional: `eza` for `ls`, `bat` for `cat`, `rg` for `grep`, `fd` for
  `find`. `ll`/`ls`/`cat` are already aliased; everything else keeps its own name.
* *`tree`*: a directory listing at a glance, without reaching for `eza --tree` or `fd` piped
  through something else.

Typing feels slower than you'd expect? <<first-day>> covers why, and the two fixes -- one of which
is switching to the `fish` persona.

=== `lefthook`: git hooks, ready to adopt

A git hooks manager is installed in every profile, ready to adopt in any project without writing
hook scripts by hand:

[source,shell]
----
$ cp templates/lefthook.yml.example ./lefthook.yml
$ lefthook install
----

Edit the copied `lefthook.yml` for the checks your project actually wants (lint, test, format)
before committing to it team-wide.

=== `sensitivectl`: back up a sensitive directory

Backs up a local directory -- SSH keys, a credentials store, anything you'd never want to lose but
also never want in git -- to any `rclone`-supported remote:

[source,shell]
----
$ sensitivectl backup ~/.ssh my-remote:backups/ssh
$ sensitivectl restore my-remote:backups/ssh ~/.ssh
----

Configure the remote itself with `rclone config` first, the same as any other `rclone` use.

=== Everything else

* *`wget`, `rclone`, `curl`*: three ways to fetch something, pinned to a reproducible version
  rather than floating with whatever the base OS shipped.
* *`git-chglog`*: generate a `CHANGELOG.md` from your commit history.
* *`make`*: GNU Make, pinned here rather than assumed from the base OS image.
* *`shellcheck`*: a linter for the language most of this repository's own tooling is written in.
* *`duckdb`*: a local analytical database, for ad hoc work with CSV/Parquet/SQL without standing
  up a server.
* *`sqlite3`*: for poking at a plain SQLite `.db` file by hand -- several official MCP reference
  servers expect one to already be there (<<ai-agents>>).
* *ImageMagick (`magick`/`identify`/`convert`) and `cwebp`/`dwebp`*: resize, inspect, and
  re-encode images, WebP included. `doctor` checks ImageMagick can actually read and write WebP,
  not just that it's installed.
* *`uv`*: a repo's own command line can fetch hash-locked Python packages on first use (`uv run`,
  `uvx`) into uv's cache under `~/.cache/uv`. Nothing goes into the profile's own Python, which is
  read-only anyway.
* *A standard Unix userland on Linux*: `sed`, `find`/`xargs`, `diff`/`cmp`, `patch`, `tar`, `gzip`,
  `zip`/`unzip`, `bzip2`, `xz`, `file`, `less`, `which`, `ps`, `hostname`, `tput`, `rsync`, `bc`. A
  real Linux machine already has these; the container images don't have a base OS, so without this
  a build script's first `sed` failed with "command not found". On a Mac only `xz` is added: GNU
  `sed` ahead of the BSD one would change how your existing scripts behave. `doctor` checks the
  whole set either way.
* *SSH agent auto-start*: a new login shell loads your key automatically.
* *`cdp`*: jumps to the current git repo's top-level directory.
