== Use AI Coding Agents Safely

=== Setting up AI coding agents

Every profile installs `nodejs`, `aider-chat`, `python3`, `uv`, the `playwright` CLI, a matching
set of Playwright browser binaries, and (on Linux) `chromium`, ready to go. The fast-moving hosted
CLIs install with their own `npm install -g`:

[source,shell]
----
$ npm install -g @anthropic-ai/claude-code   # provides: claude
$ npm install -g @openai/codex               # provides: codex
$ npm install -g @google/gemini-cli          # provides: gemini
----

`python3`/`uv` are there for the other half of the ecosystem: most MCP servers an agent's own
`.mcp.json` references are Python packages launched with `uvx <package>`, no separate install step
needed, the same way `npx` works for a Node-based one. The Playwright browser binaries and
`chromium` are there for browser-automation MCP servers specifically -- Playwright MCP, the
official Puppeteer MCP server, and others built the same way -- so the first time you add one, it
finds a browser already on this machine (`PLAYWRIGHT_BROWSERS_PATH`, and on Linux
`PUPPETEER_EXECUTABLE_PATH`, point at it) instead of downloading its own. `chromium` itself is
Linux-only -- nixpkgs doesn't build it for macOS -- so on macOS a Puppeteer-based server still
downloads its own browser the first time; a Playwright-based one doesn't, on either platform. The
`playwright` CLI itself (`playwright codegen`, `playwright test`) is there too, for driving a
browser directly instead of only through an MCP server, version-locked by nixpkgs to the exact
browser revision already installed. No persona required for any of this to work.

Give one its key by adding it to your credentials file (<<your-name-email-and-any-api-keys>>) and
running `workspaces-host-update`. Each CLI's key is scoped to that one invocation, never exported
to your whole shell: `echo $ANTHROPIC_API_KEY` stays empty even after `claude` has used it (see
<<why-secret-scoping>> for why that matters). `doctor` checks whether each CLI is installed and
whether it has a key.

If a CLI has its own browser-based `login` instead of an API key -- Claude Code and Gemini CLI both
do -- that works too; the credential wrapper is a transparent no-op when nothing's configured.

=== Try with AI

Every prompt in this book assumes you already have an agent running in this sandbox. Once you do,
these are worth keeping handy.

*Diagnose a problem:*

....
Run doctor --all in my sandbox, explain any FAIL or WARN lines in plain language, and tell me
exactly what to do to fix each one.
....

*Start a new project, agent-ready from the first commit:*

....
Create a new project folder in ~/workspaces called my-project, run scaffold-agent-harness in it,
and show me what files it created.
....

`scaffold-agent-harness` drops a starter `AGENTS.md`, an `.mcp.json`, and a `.claude/settings.json`
into any project, not just this one -- the same idea applied to whatever you're building next.

TIP: These prompts are starting points, not magic words. Your agent may ask a clarifying question
or do something slightly different depending on what it finds on your machine. That's normal:
answer it and keep going.
